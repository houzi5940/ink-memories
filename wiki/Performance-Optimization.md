# 性能优化与交互优化

记录 InkMemories 在人工审核、图片加载、每日精选等方面的优化。

## 人工审核交互优化

### 乐观更新（Optimistic UI）

**问题：** 点击"开始评分"后，前端需要等待后端 API 返回 + 重新扫描 NAS 照片目录，整个页面卡在加载动画中。

**优化：** 提交后立即从页面上移除已处理的照片，后台静默刷新最新数据。

```
之前：提交 → 等 API → 等 os.walk(慢) → 全页 loading → 显示
现在：提交 → 等 API(快) → 照片瞬间消失 → 后台静默同步
```

### 图片比例自适应

**问题：** 审核页三种模式（平铺/滑动/按月）中，图片被强制裁为正方形或 4:3。

**优化：** 移除固定 `aspect-ratio` 约束，图片按自然比例显示（`w-full h-auto`）。

### 图片加载速度优化

#### HEIC→JPEG 磁盘缓存

**问题：** 每次请求 HEIC 照片，后端都要从 SMB NAS 读取原图 + 解码 HEIC + 全尺寸转码 JPEG，十分耗时。

**优化：**
- 首次转码后缓存 JPEG 到 `/data/photo_cache/`
- 缩放到最大 1920px（质量 85），相比全尺寸大幅缩小体积
- 缓存键包含源文件 mtime，源文件变化时自动重缓存
- 所有后续请求直接 `FileResponse` 返回缓存文件，毫秒级响应

#### 审核扫描结果缓存

**问题：** `scan_unanalyzed_photos()` 每次请求都 `os.walk` 遍历 SMB 挂载的 NAS 照片目录（数千张），耗时数十秒。

**优化：**
- 内存缓存 `_scan_cache`，30 秒 TTL
- 提交/跳过操作时自动清除缓存
- 同一会话内重复进入审核页毫秒级返回

## 每日精选优化

### 缓存固定一天

**问题：** 每次刷新首页，随机选取的照片都会变化，且需要重新调用 VLM API 生成描述。

**优化：**
- 新增 `daily_selection` 表，每日精选照片缓存一天
- 每天首次访问时生成并缓存，后续访问直接读取
- 每日凌晨 3:00 自动刷新（Hermes cron `POST /api/daily/refresh`）

### 加权随机不重复

**问题：** 照片池较小时，同一批照片可能连续被选为今日精选。

**优化：**
- 新增 `last_daily_used` 字段追踪照片最近选用时间
- `_pick_weighted()` 优先选 60 天内未用过的照片
- 只有候选不足时才降级到已用过的照片

## 相册筛选优化

### 类型多选

**问题：** 相册页类型筛选只能单选，每次换分类都要重新点击。

**优化：**
- 类型筛选支持多选：`?type=人物,旅行`（OR 匹配）
- "跳过"筛选与其他类型互斥

### 默认隐藏跳过照片

**问题：** 相册页展示大量被标记为"跳过"的低质量照片。

**优化：**
- 默认 `WHERE status != 'skipped'`
- 点击"跳过"筛选按钮可查看所有跳过照片
